# HTML-страницы базы знаний — стиль, устройство, проверка

## Что читать

В шаблоне и в каждой странице около 55 КБ занимают общий CSS (`<style id="wiki-css">`) и движок схем (`<script id="wiki-engine">`). Для работы нужен остальной текст файла:

- **Тело шаблона или страницы без CSS и движка:**
  ```bash
  awk '/<style id="wiki-css">/||/<script id="wiki-engine">/{s=1} !s{print} /<\/style>/||/<\/script>/{s=0}' "<файл>.html"
  ```
- **Справка по движку** — все поля `WIKI.flow` и `WIKI.seq`, 3 КБ:
  ```bash
  sed -n '/<section class="card" id="ref">/,/<\/section>/p' /home/ev/code/personal/wisp/_templates/Заметка.html
  ```

Выбери образец по задаче.

В конце файла — их вызовы `WIKI.flow` и `WIKI.seq`.
2. **Готовая страница** из `/home/ev/code/personal/wisp/html/`, ближайшая к задаче:

   - `scst.html`, часть «Архитектура SCST» — flow с дорожками, узлы-ссылки `href`;
   - `2pc-2-phase-commit.html` (2PC (2-phase commit)) — схема обмена сообщениями, 6 вариантов стопкой;

## Запреты

- **Интерактив — только виджетом** (раздел «Виджеты» ниже). Уже написанные разделы под виджет без просьбы не переделывай: виджет появляется, когда пишешь новую заметку, часть или раздел.
  - **Можно:** кнопки, переключатели (radio, checkbox), поле для числа, строка статуса с пояснением шага, перерисовка содержимого виджета после действия, подсветка ровным фоном функции в коде, которая только что выполнилась.
  - **Нельзя:** выезжающие и сворачивающиеся панели, `details`/`summary`, вкладки, всплывающие подсказки (`title=` у ссылок и узлов), реакция на наведение (hover-подсветка), свечение, тени, пульсация, анимация и плавные переходы, модальные окна, кнопка смены темы.
  - Схемы движка `WIKI.flow` / `WIKI.seq` остаются статичными.
  - Поле поиска в верхней панели (форма на `index.html?q=…`, клавиши `/`, Ctrl+K) и сообщение главной (`postMessage`) ставят `create` и `sync`, руками не трогать.
- **Схемы — только через движок** `WIKI.flow` / `WIKI.seq`. Нельзя: Mermaid, PlantUML, картинки, готовые SVG-файлы, внешние библиотеки, CDN, `<link rel=stylesheet>`, `@import`.
- **Не править:**
  - блоки `wiki-css` и `wiki-engine` в страницах — их перезаписывает `sync` из шаблона;
  - `_templates/`, `scripts/`;
  - `html/index.html` руками.

  Нужна новая возможность стиля или движка — предложи пользователю, сам не меняй.

## Устройство страницы

Команда `wiki_html.py create` собирает страницу из шаблона.

- Каноническое название хранится в `wiki-meta.title`, `<title>` и `h1`. Имя файла назначает `create`. Адрес существующей страницы выдаёт `file "<имя заметки>"`.
- **`<head>`:**
  - `<title>`;
  - `<link rel="icon">` — иконка вкладки по разделу (цветная плашка со значком, SVG в `data:`). Ставят `create` и `sync` по `section`/`sub` из meta, руками не править. Для нового раздела иконки нет (будет серая «Входящие») — предложи пользователю добавить её в `ICON_COLOR`/`ICON_GLYPH` скрипта;
  - `<meta name="description">` — первый абзац простым текстом;
  - `<script type="application/json" id="wiki-meta">` — `title`, `aliases`, `tags`, `term`, `section`, `sub`, `order`, `level`, `status`, `parent`, `source`, `version`, `updated`. Поле `md` встречается у импортированных страниц.
  - `wiki-tips` — словарь «имя заметки → файл страницы» для узлов-ссылок, заполняет `links`;
  - `wiki-css`.
- **`.top`** (закреплена при прокрутке) — «База знаний» → `index.html`, поле поиска `form.ix-search.pg` (Enter открывает результаты на главной), раздел (текстом, без ссылки), навигация по `h2`. В окне просмотра главной (класс `in-frame` на `<html>`) вся панель `.top` скрыта (пользователь попросил убрать шапку): навигацию заменяет карточка «Содержание».
- **`.wrap`:**
  - `h1`;
  - `p.sub` — первый абзац простыми словами;
  - `.meta` — плашки уровня, статуса, версии у SCST;
  - `.intro` — текст перед разделами, если нужен.
  - `section.card` с `id` и `h2` на каждый раздел. `create` строит карточки по аргументам `--heading`.
  - `footer.foot` — дата правки страницы.
- **Slug заголовка** — `id` карточек и якоря ссылок: нижний регистр; всё, кроме букв, цифр, `_`, пробелов и дефисов, убрать; пробелы заменить дефисом. `Где встречается в SCST` → `где-встречается-в-scst`, `На примере: хост подключается к СХД` → `на-примере-хост-подключается-к-схд`. Второй такой же заголовок на странице получает `-2`.
- **Оглавление** — `section.card#содержание` перед первым разделом. `create` заполняет его заголовками карточек. При добавлении `h3` вложи ссылки на подразделы в `ul`. Верхняя навигация перечисляет основные разделы.
  ```html
  <section class="card" id="содержание">
  <h2>Содержание</h2>
  <ol class="toc">
    <li><a href="#раздел">Раздел</a>
      <ul>
        <li><a href="#подраздел">Подраздел</a></li>
      </ul>
    </li>
  </ol>
  </section>
  ```
  `href` — `id` карточки или `h3` (slug заголовка), `check` проверяет, что такие якоря есть.
- **Конец страницы:** `wiki-engine`, затем `<script>` «Схемы страницы» — сюда добавляются вызовы `WIKI.flow(...)` и `WIKI.seq(...)`.
- **Ссылки:**
  - другая страница — `<a class="wl" href="lun-logical-unit-number.html">LUN</a>`. Имя файла транслитом.
  - на часть SCST — `href="scst.html#<slug части>"`;
  - заметки ещё нет → `<span class="wl planned" data-target="X">текст</span>`. Когда она появится, `links` превратит его в ссылку.
- **Прочее:**
  - справочная выноска — `div.callout`.
  - пункт списка задач — `li.task` с `.cb`.
  - таблицы → `div.tbl > table.tr`;
  - «См. также» → чипы `ul.chips`.

## Схемы

1. Для статичной схемы вставь контейнер в карточку.
   ```html
   <div class="svg-scroll"><svg class="dia" id="svg-<короткий-id>" role="img" aria-label="<что на схеме>"></svg></div>
   ```
   Перед ним при желании `<p class="lead">` — что показано и как читать. В скрипт «Схемы страницы» добавляется вызов движка.

   Для интерактивной модели используй разметку `.wg` из раздела «Виджеты».
2. Подписи по-русски, имена функций и протоколов сохраняют своё написание. Перенос строки — `\n`.
3. **Какой вид выбрать:**
   - **flow** — блоки и связи. Координаты явные, `x`/`y` — центр блока. Рёбра не пересекают блоки, подписи не налезают на блоки; при необходимости `fs`/`ts`, `fo`/`to`, `via`, `lp`. Слои — дорожками `lanes` (`ext drv core dh svc hw`) или полосами `rows`;
   - **seq** — обмен сообщениями: `parts`, `msgs` (`{sep}` — фаза, `{gap}` — пауза, `{note}`), `blocks` (`k: hw grp err alt`). Сценарии `alt` / `opt` → `variants`, движок нарисует их стопкой с подписями;
   - **автомат состояний** — flow с `k: "init"` и `k: "final"`;
   - **группы компонентов или пакетов** — flow с дорожками или полосами.
4. **Виды узлов `k`:**

   | `k` | Что обозначает |
   |---|---|
   | `ext` | внешний участник, хост, программа |
   | `drv` | драйвер, транспорт |
   | `core` | ядро, логика |
   | `disk` | хранилище; `shape: "db"` — цилиндр |
   | `hw` | железо |
   | `thr` | поток |
   | `q` | очередь |
   | `dec` | развилка «да / нет» |
   | `err` | ошибка |
   | `pause` | ожидание |
   | `note` | особый случай |
   | `focus` | тема этой заметки |
   | `ghost` | нет в этом варианте |

   **Рёбра** `cls`: `dash` (ответ, косвенная связь), `err`, `hw`, `chg`. Легенда строится сама; подписи можно переопределить через `legend`. Для схем СМО с несколькими видами заявок есть цвета `data` (синий), `tm` (фиолетовый), `cfg` (бирюзовый), `sess` (оливковый); образец линии в `legend.extra` — `"border-color:var(--e-tm)"`. Ребро без `cls` — серое: смешанный поток.

   **Значки СМО** (система массового обслуживания: источники, очереди, потоки, краны) — поле `q` вместо блока: `src` ▶ источник, `queue` очередь, `thr` поток (часы), `irq` прерывание, softirq, tasklet (молния), `hold` кран, `fork` развилка, `lost` отказ, `sink` сток, `ctl` запись в файл (sysfs), `step` действие в том же потоке. `many: true` — стопка, таких несколько. `own: "ядро"` — метка «чьё» в строке заголовка, со стороны значка: на что заведены очередь, поток или кран (`порт`, `ядро`, `соединение`, `пара`, `том`, `заявка`); `own: "СХД", oc: "all"` — одна на всю систему, метка залита. Метка бывает только у значка `q`. Текст рядом со значком: `tp: "r" | "l" | "t" | "b"`, над или под боковой стрелкой — `"rt" | "rb" | "lt" | "lb"`. Стрелки цепляются к значку. Образец с легендой классов — раздел «Система массового обслуживания для 3.9 и 4.1.0» в `scst-mashina-sostoyaniy-komandy-3-9-i-4-1-0.html` (`svg-smo-leg`, `svg-smo-39`, `svg-smo-41`).
5. **Ссылки с узлов.** Узел, которому соответствует другая заметка базы, получает `href:` **именем заметки**, не файла: `href: "LUN (Logical Unit Number)"`, `href: "SCST#<slug части>"`. Адрес файла движок берёт из `wiki-tips`, поэтому ссылкой узел станет только после `links`, если страница есть.
6. **Нумерованные шаги рядом со схемой** → `.split`: схема слева, `ol.steps` с `li.step` справа (`span.num` и `div` с `h4` и текстом).
   - Номера `n` на схеме = номера шагов. Номер в тексте и таблицах — `<span class="ref">N</span>`.
   - Код шага вместо номера — буква и одна цифра: в кружок `n` входят два знака, третий обрезается. Буквы З и О не брать: в шрифте страницы они читаются как 3 и 0.
   - Шаги железа: `<span class="tag hw">⚙ железо</span>`, на seq — `blocks` с `k: "hw"`.
   - Шаги под схемой — `section.card.stack`.
7. **Размер.** `vw`:
   - в обычной карточке — до ~1150;
   - внутри `.split` — до ~760.

   Без больших пустот и крошечных шрифтов. Лучше две схемы, чем одна перегруженная.

## Виджеты

Модель, которую можно пощёлкать. Эталон — карточка «Виджет» (`#widget`) в `_templates/Заметка.html` и разделы 1–2 в `html/struktury-dannykh.html`.

Добавляй виджет, когда читатель может изменить вход, шаг или сбой и увидеть результат по правилу. Один виджет раскрывает одну идею. Для термина достаточно одного, для раздела — до двух. В «Работе» добавляй виджет по просьбе.

**Четыре образца — выбрать подходящий:**

- **Входы → результат.** Читатель переключает входы или меняет число, виджет сразу пересчитывает выход, а строка статуса объясняет его на этих значениях (`1 AND 0 = 0: нужны оба входа 1`). Подходит для вентиля, формулы, расчёта адреса.
- **По шагам.** Кнопки «← назад» и «дальше →», на каждом шаге подсвечено, кто сейчас работает и какие данные читает. Подходит для пути данных и протокола.
- **Переключатель сбоя.** Отвечает на «зачем»: включаешь «битая контрольная сумма», «чужой адрес», «питание пропало», и видно, на каком шаге и почему всё ломается или спасается.
- **Угадай → проверь.** Сначала читатель выбирает ответ кнопкой («куда попадёт запись?»), потом строка статуса показывает и объясняет правильный.

**Страница понятна и без кликов.** Многие читатели не нажимают кнопки, поэтому всё нужное говорит текст вокруг виджета, а виджет даёт проверить и увидеть случаи руками. Строка статуса пишется обычными словами — кто, что сделал, почему. Имена функций в ней не нужны: их показывает подсветка в `pre.wg-code`.

**Устройство** — классы из `wiki-css`, без своего CSS в странице:

```html
<div class="wg" id="wg-<id>" role="group" aria-label="<что моделирует>">
  <div class="wg-lab">int a[6]</div>                 <!-- подпись над рядом -->
  <div class="wg-cells" id="wg-<id>-cells"></div>   <!-- ряд .wg-cell: .on .hit .bad .ok .other; номер — <small> -->
  <div class="wg-row">…кнопки, label с input, span.sep…</div>  <!-- button.main — главное действие, .danger — сбой, .sq — − и + -->
  <div class="wg-legend">…<span><i class="hit"></i>что значит цвет</span>…</div>
  <div class="wg-status" id="wg-<id>-msg" aria-live="polite"></div>  <!-- .bad / .good -->
</div>
<pre class="wg-code" id="wg-<id>-code"><code><span class="fn" data-fn="get">…функция…</span><span class="fn" data-fn="set">…</span></code></pre>
<script>
(function () { /* состояние, draw(), обработчики кнопок; выполненная функция → .fn.hit */ })();
</script>
```

- Столбцы (диски, страйпы) — `.wg-cols > .wg-col` с `<b>` заголовком и ячейками.
- Связь между ячейками (список, `next`) — `<span class="arr">→</span>` внутри `.wg-cells`.
- Дерево (куча, дерево поиска, дерево Меркла) — `.wg-tree`: каждый уровень — `<div>`, в нём 2^уровень мест `<span>` равной ширины, узел — `.wg-cell` внутри места, пустое место — пустой `<span>`.
- Путь данных или обмен сообщениями — ряды `.wg-cells`: ряд на участника или слой, текущий шаг — подсвеченная ячейка и строка статуса.
- **Строка статуса** объясняет каждый шаг на числах: что вычислено и почему (`адрес = 1000 + 3 × 4 = 1012`). Ошибка и опасный момент — `.bad`, удачное восстановление — `.good`.
- **Код под виджетом** — короткий, только ядро. Каждая функция — `span.fn[data-fn]`. Между `</span>` и следующим `<span class="fn">` нет перевода строки: `.fn` — блок, лишний `\n` даст пустую строку. Комментарий — `span.c`.
- Скрипт — IIFE сразу после кода, только своё состояние и элементы со своим `id`. Начальное состояние — уже что-то показывающее (пара записей, не пустой ряд) и первая строка статуса подсказывает, что нажать.
- Нельзя (см. «Запреты»): hover-эффекты, анимация и переходы, тени, сворачивание, подсказки, модальные окна. Цвета — только переменные `wiki-css`.
- `check --screenshot` ловит ошибки скрипта виджета в Chrome. На снимке проверь начальное состояние ячеек и строку статуса.

## Подача текста

Для термина подойдут карточки «Точнее», «Где встречается» и «См. также». В первом абзаце выдели термин через `strong`, расшифровку через `em`. Статью удобно начать с конкретной ситуации и разбирать её дальше по разделам.

Внутри карточки выбирай разметку по смыслу.
- `.changes` (блок «главное») — для явных итогов и выводов;
- `dl.gl` — для списков «термин — пояснение»;
- **ASCII-схема в коде** (стрелки, рамки), которая рисует поток или структуру, → `WIKI.flow`. Вывод команд и конфиги остаются кодом;
- **формулы LaTeX** → `<div class="formula">`:
  - `<var>` — переменные;
  - `<sub>`, `<sup>`;
  - дробь — `<span class="frac"><span>числитель</span><span>знаменатель</span></span>`;
  - знак суммы — `<span class="big">∑</span>`.

## Команды `scripts/wiki_html.py`

| Команда | Что делает |
|---|---|
| `create ИМЯ --section РАЗДЕЛ --summary ТЕКСТ --heading ЗАГОЛОВОК` | Автономная HTML-страница с первым абзацем, оглавлением и карточками. Повторяй `--heading`, `--alias`, `--tag` по необходимости |
| `links --edited ИМЯ [ИМЯ ...]` | Оживляет запланированные ссылки, собирает `wiki-tips`. Для перечисленных страниц берёт дату из HTML и снимает привязку к прежнему источнику |
| `index --html-only` | Обновляет данные поиска и список заметок из HTML |
| `sync` | `wiki-css` и `wiki-engine` из шаблона во все страницы (после правки шаблона) |
| `check --html-only [--only ИМЯ] [--render]` | Проверяет метаданные, разделы, ссылки, якоря и автономность страниц. `--render` дополнительно проверяет схемы в Chrome |
| `file ИМЯ` | Выдаёт локальный адрес страницы |

## Проверка страницы

Для снимков используй `$CLAUDE_JOB_DIR/tmp`, если он задан, иначе `/tmp/wiki-<имя>/`. Для текста и ссылок достаточно общего `check --html-only`. Новую страницу, новую схему, виджет или изменение вёрстки проверь в браузере. Опция `--screenshot` выполняет проверку DOM и сохраняет снимок за один запуск Chrome. ## Работа

При пошаговом разборе добавляй ровно запрошенный шаг, схему или раздел. На уточняющий вопрос отвечай в чате. Вид схемы задаёт пользователь, виджет добавляй по просьбе.

- Алгоритм покажи на схеме и в нумерованных шагах. На схеме каждого шага отрази крайние случаи, чтения, записи, изменения счётчиков и таймауты. Укажи, что может потеряться и где заканчивается разбор. Повторяющееся действие вынеси в отдельный алгоритм. Код шага — буква и цифра, кроме букв З и О.
- Для структуры данных дай целый пример, затем по абзацу на поле в порядке записи. Объясни назначение каждого поля, значения перечисления оформи списком. Для этого разбора достаточно примера и текста.

## Большая заметка SCST (`html/scst.html`)

Добавляй часть по образцу соседних. Порядок чтения идёт от общей картины и основ железа к блокам SCST и терминам.

- Для блока укажи уровень L0/L1/L2, статус, путь к коду от корня репозитория, родительскую часть и синонимы. В начале разбора проведи через блок одну команду.
- После «Коротко» идут «Место в общей картине», «Как устроено», «На железном уровне», «Ключевые структуры и функции», выноска «Форк Aerodisk», «Открытые вопросы» и «Дальше».
- Внутреннему термину достаточно определения, примера, уточнения, мест использования в SCST и связанных тем.
- При добавлении части обнови `wiki-meta.aliases` и ссылки на неё. Убери готовую часть из «Плана разборов».

```html
<div class="part">
<h2 class="part-h" id="<slug части>">Название части</h2>
<p class="sub">…первый абзац («Коротко»)…</p>
<div class="meta"><span class="pill lvl">L1</span><span class="pill st-draft">черновик</span>…</div>
<section class="card" id="<slug части>--<slug подраздела>"><h3 class="ch">Подраздел</h3>…</section>
…
</div>
```

- **«Коротко»** становится `p.sub` части, отдельной карточки у него нет.
- **Плашки**: уровень — `pill lvl`; статус — `pill st-draft` (черновик), `st-ok` (понятно), `st-verified` (сверено с кодом).
- **Якоря**: часть — `slug(Название)`, подраздел — `slug(Часть)--slug(Подраздел)`.
- **Схемы**: `id="svg-pN-…"`, N — номер части. Новой части дай свободный номер, даже если она стоит в середине: номер нужен только для уникальности `id`. Занятые покажет `grep -o 'id="svg-p[0-9]*' /home/ev/code/personal/wisp/html/scst.html | sort -u`. Вызовы движка части — в своём блоке `(function () { … })();` внутри скрипта «Схемы страницы».
- **Узел-ссылка** на часть: `href: "SCST#<slug части>"` (имя заметки); ссылка в тексте — `href="scst.html#<slug части>"`.
- **Порядок карточек** в начале и в конце: Содержание, Общая картина, … части …, Термины, План разборов, Как устроена эта заметка. Новую часть добавить в «Содержание» (`ol.toc` с плашками уровня и статуса). Верхняя навигация перечисляет группы, а не части (Общая картина, Железо, Ядро, Target drivers, Device handlers, Userspace, Термины): часть попадает в неё, только если открывает новую группу.
